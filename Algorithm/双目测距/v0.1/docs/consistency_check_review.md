# v0.1 左右对应检查结果与误差原因

日期：2026-11-20。已完成：左右对应检查、原43对固定输入的前后对比，以及误差诊断。版本仍为 v0.1。

## 1. 新增功能做了什么

以前只由左图寻找右图。现在开启检查后，还会独立运行一次右图到左图的 SGBM。

例如左图 x=300，视差为20，则先查右图 x=280。如果右图认为这个点返回左图 x=300，往返一致；如果返回 x=304，误差4像素，本次会排除。右图坐标为小数时采用线性插值，插值需要的邻点也必须有效。

本次往返误差门槛固定为 **1像素**。左SGBM参数、相机矩阵、43对输入、人工测距ROI及区域输出门槛均保持原值。参考距离仅用于事后算误差。原始结果保存在旧目录，新结果另存。

本机不含 ximgproc，因此用原有 StereoSGBM 独立计算右图。右图搜索区间为−127～0，左图为0～127；其余匹配参数继续沿用原配置。该负视差区间与 [OpenCV官方右匹配器源码](https://github.com/opencv/opencv_contrib/blob/4.x/modules/ximgproc/src/disparity_filters.cpp) 的定义一致；没有照搬源码中放宽唯一性、散斑等设置的默认选项。

## 2. 实际效果：拦下2张，但未改善整体精度

| 项目 | 检查前 | 开启检查后 |
| --- | --- | --- |
| 输出距离 | 43/43对 | 41/43对 |
| 纸盒25对平均绝对误差 | 12.48 cm | 12.56 cm |
| 人物9对平均绝对误差 | 32.17 cm | 32.29 cm |
| 同样能够输出的41对，平均绝对误差 | 44.68 cm | 93.60 cm |
| 相对误差≤20%的图片数 | 36/43 | 35/43 |

`PartC/0004`（约1米椅子）和 `PartC/0010`（约2米椅子）筛点后有效比例降至约7.7%、7.5%，低于原有10%门槛，因此不再输出距离。

但 `PartC/0012` 从 **3.888 m** 变为 **24.302 m**，而参考记录为1.99 m。原因可以从数组直接看到：原ROI有效深度中，超过10米的点占 **36.2%**；检查后占 **57.4%**。错误深度变成多数，中位数就落到远处。这不是程序把距离乘大了，而是筛点改变了剩余数据的组成。

因此，本次新增的是可用的**对应检查工具**，还没有得到“精度提高”的结果。它检查两次匹配是否相互同意；同意的错误对应仍可能通过。

## 3. 原因一：当前左右图的同一点还有上下错位

对纸盒上的图案，使用独立的 SIFT 特征互相匹配，允许查看二维位置，再统计同一候选点在左右校正图中的行号差。该方法只作诊断，不接入正式测距。每对候选数量、位置均已保存，近距离纸盒每对有数十个，远距离每对约4～12个。

| 纸盒距离组 | 左右行号差中位数的组平均 | 直观解释 |
| --- | --- | --- |
| 0.5米 | −4.97 px | 同一图案在右图约低5像素 |
| 1米 | −2.17 px | 约低2像素 |
| 1.5米 | −2.20 px | 约低2像素 |
| 2米 | −1.75 px | 约低2像素 |
| 3米 | −1.39 px | 约低1～2像素 |

当前 SGBM 沿同一行寻找对应。真实图案若在右图低了2像素，算法仍在原行比较，容易把相似纹理当成对应；左右反查也沿同一行，所以反查不能自动解决这一问题。

这些数据确认了**当前图像与严格同一行匹配的假设有差异**。差异随距离变化，不能简单地把右图统一上移2像素就认为全部解决。来源可能包含现有几何关系与实际拍摄状态的差异；本轮没有重新估计标定参数。

## 4. 原因二：纸盒整体偏近，有方向定义差异，也有剩余系统偏差

程序输出的是矫正后坐标的 Z。相机矫正改变了坐标方向，因此这个Z与原左镜头朝向的Z不是完全相同。[OpenCV官方说明](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html) 给出了 Q 重建的坐标定义，以及 R1 在矫正前后坐标之间的作用。

本轮仅作诊断：对原有三维点应用 R1 的逆旋转，观察换回原左镜头方向后的数值。没有替换正式输出，也没有改矩阵。

| 纸盒距离组 | 原输出平均绝对误差 | 换回原左镜头方向后的诊断误差 |
| --- | --- | --- |
| 0.5米 | 3.15 cm | 2.38 cm |
| 1米 | 5.35 cm | 2.57 cm |
| 1.5米 | 10.12 cm | 7.29 cm |
| 2米 | 15.77 cm | 11.63 cm |
| 3米 | 27.99 cm | 21.43 cm |
| 合计25对 | 12.48 cm | 9.06 cm |

方向定义解释了**部分**差异。现场卷尺的朝向与起点记录不够细，不能直接把这个诊断结果当成最终修正值。

剩余偏差也不全是 SGBM 单独造成的：用纸盒图案候选的横坐标差独立计算诊断深度，换回原左镜头方向后，1/1.5/2/3米组的平均值约为 **0.976/1.429/1.881/2.739 m**，仍然整体偏近。图案点与测距ROI的采样位置有所不同，这里用于确认趋势。

在“参考值就是原左镜头前方距离”的假设下，1～3米组仍表现出约 **1.1～1.5像素**的额外视差。现有数据可以确认偏差趋势，但不能单独区分是几何参数中的哪一项、距离起点还是现场距离定义造成。已核验的5.85 cm只确定基线长度，不能单独确定所有投影关系。

远距离对这点误差更敏感：当前 `fB≈42.53像素·米`，按 `Z=fB/d`，3米附近1像素变化对应约21厘米深度变化，1米附近约2.4厘米。SGBM的1/16像素输出步长，在3米处对应约1.3厘米变化，量级不足以解释28厘米误差；输出步长也不等于匹配精度。

## 5. 原因三：椅背存在不可靠的深度混合

近处椅背上沿很窄，测量框高仅8～12像素。内部纹理弱、局部重复，相邻匹配窗口还会覆盖边缘和其他表面。本轮在这些窄框内没有得到可用的 SIFT 图案对应；这表示该诊断方法也缺少可核对的图案，不代表椅子一定无法测量。

更直接的证据是深度分布：`0010～0012` 的原ROI四分位距分别约 **2.45/2.53/27.49 m**，说明ROI中的结果分散在不同距离，已不符合“一个物体表面大致一个深度”的期望。左右检查没有识别物体或区分深度簇，因此错误簇仍能留下，0012就是明显例子。

后续需要讨论的是区域内哪些点真正代表待测表面，以及何时明确不给距离。单独提高有效像素数量，或只看反查通过率，都不够。

## 6. 人物0015：更符合左右拍摄期间的人物变化

在外套和躯干周围，核对到以下互相匹配的图案候选；它们用于诊断，不替换原来的衣服中央测距ROI。

| PartC编号 | 图案候选数量 | 图案横向差中位数 | 原SGBM测距ROI视差中位数 |
| --- | --- | --- | --- |
| 0013 | 162 | 15.13 px | 15.69 px |
| 0014 | 147 | 14.95 px | 16.00 px |
| 0015 | 135 | 20.45 px | 21.75 px |

0015的额外横向差，在明显图案上也存在，因此不能把约1.96米的异常全部归为衣服中央的SGBM错配。

继续比较0013与0015：

- 每侧跟踪200个背景点，背景位移的中位数在各坐标方向上均小于0.04像素，相机和背景整体基本稳定。
- 人物外套的表观尺度只变化约2%～3%，不符合从约3米靠近到约2米时应出现的明显放大。
- 同一外套区域在左图中的横向变化约−0.58像素，右图约−5.99像素，两者相差约5.4像素。

这些证据**更支持人物在左右依次拍摄期间发生横向位置或姿态变化**，而不是整个相机移动。仅凭照片不能恢复准确动作时间，但在3米处约2厘米的横向变化，就能产生约5像素额外位移，量级与观察一致。

这一类输入即使找到真实的衣服图案，也会把人物移动混入视差；左右一致性可能照样通过。0015应保留为“疑似人物变化”的困难样例，用于理解系统表现，不拿它单独牵引静态匹配参数。

图案对应可直接查看：0013（历史本地材料未随发布副本携带）、0014（历史本地材料未随发布副本携带）、0015（历史本地材料未随发布副本携带）。

## 7. 下一步建议，等待选择

建议下一步先针对**纸盒的局部对应**做一次可解释的匹配方案对照：保留左右完整二维坐标，比较同一行搜索与允许少量纵向偏移的候选位置，观察上下错位对视差的实际影响。这是现有输入上的算法实验，不是重新标定；二维对应与深度计算使用的几何关系要一起说明，不能只改图像位置却沿用不相符的深度关系。

接着再讨论**椅背等困难区域的深度簇与质量判断**，明确何时输出距离、何时提示需要换一个可测表面。人物0015的运动因素单列分析。

现有数据足够开展上述比较，不新增采集任务。本轮没有开展这些后续方案，也没有进行窗口、惩罚或一致性门槛的试调。

## 8. 如何使用、保存在哪里

单对开启检查，在 `Algorithm/双目测距/v0.1` 中运行：

```bash
python run_ranging.py --check-consistency --out results/my_consistency_01
```

43对批量开启检查：

```bash
python evaluation/evaluate_dataset.py --check-consistency --out results/my_consistency_batch
```

输出目录取新名字。旧命令不加开关时维持原方法。要复现本轮某对图片的实际配置，使用其 `config_resolved.json`，里面已记录 `consistency.enabled=true` 和 `max_diff_px=1.0`。

新增内容：

- `result.json` 中 `before_consistency`：检查前的原区域统计与误差；`consistency_check`：可比较点数、通过点数、通过比例、往返误差中位数。
- `arrays.npz` 中右视差、右图有效掩码、检查前掩码和深度、可比较掩码、逐点往返误差。
- `consistency_mask.png`：绿色通过、红色往返超限、蓝色无有效右点可比较、黑色原本无效。
- 原有深度、有效掩码和区域距离：开启开关时使用检查后的点。

检查门槛可在配置的 `consistency.max_diff_px` 调整，单位为像素；本轮全程固定1.0。通过比例表示匹配的一致程度，不是测距准确率。

本机平均读取与计算耗时约108→177 ms/对；其中独立右匹配约65 ms、掩码及检查约17 ms，均不含结果文件写盘。这是两轮电脑离线计时，不能直接作为树莓派帧率。
