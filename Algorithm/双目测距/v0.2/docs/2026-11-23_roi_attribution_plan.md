# v0.2后续方案：固定ROI规则，区分选区与匹配的影响

日期：2026-11-23。遵循本地开发流程。状态：待用户选择和批准；本次仅整理证据与方案，未实施新算法或重跑实验。

## 一、直接回答当前问题

当前v0.2的局限不全由ROI决定，但已有证据表明，我人工选取的椅子ROI限制了效果，并限制了此前结论的适用范围。

1. 原上沿框高8～12像素，最窄的8像素框无法容纳完整9×9的NCC窗口。代码只要求中心点在ROI内，并没有要求整个窗口在同一目标表面上。这使原选区不适合作为椅子整体可测性的代表。窗口跨出框不必然就是背景，但不能再声称窗口只看了原指定表面。
2. 保持NCC和门槛不变，边框网格在9对中的6对出现可输出候选，原窄上沿为0对；说明候选位置确实重要。但候选区面积、点数和表面也有变化，这不是纯粹只改变一项变量的准确率对照。
3. 主动角点在相同边框仍不足30点，而网格有部分输出，说明选点方式与门槛也影响结果。
4. 扩大内部ROI后约1米位置仍测为1.66～1.73米，证明换框本身不能解决所有问题。3米书本还存在稀疏点不足30个的输出限制，人物0015存在疑似拍摄期间变化，不能都归因于椅子的ROI。

所以，我应把原上沿试验解释为“这个人工选区配合当前算法失败”，而不是“椅子整体无法测距”。原上沿为了对应采集记录而选，但没有同时考虑匹配窗口和可用纹理，这部分选区设计需要改进。

## 二、推荐先做什么

推荐P1：**把人工挑选多个局部框，改成由完整可见椅背范围生成固定左右侧带，再比较选点。** 这是ROI生成规则的更新，同时保留NCC不动；不是先更换匹配算法，也不是继续按测得误差挑框。

完整可见椅背轮廓仍需人工标注，明确保留人工输入；程序只自动生成侧带和选点，尚不称为自动检测椅子。每张左右侧带都参与，不按距离记录或编号决定选左边还是右边。输入不读取1/2/3米分组标签。

先分别报告左右侧带结果，不自动挑“较近的”“点更多的”作为最终椅子距离。聚类和目标深度组选择留给后续单独批准。

## 三、算法说明卡

### R1：目标范围到左右侧带的相对坐标生成

- 所属环节：ROI生成。
- 功能：让不同图片使用同一选区规则，不依赖我逐张指定最有希望的局部位置。
- 输入：校正左图上人工标注的完整可见椅背轮廓及包围框，坐标为像素；标注时不展示测距数值。
- 输出：左右侧带及它们与椅背轮廓的交集掩码；交给选点和窗口检查。
- 原理：按椅背宽高比例切出左右边缘区域，裁去上、下部分；范围随目标大小变化。
- 待选方案：有。固定相对侧带（推荐，简单且能先复用已有匹配）；逐图人工局部框（已有结果，位置灵活但主观性大，只作基线）；边缘/直线自动定位（能进一步减少人工输入，但重复网纹和遮挡会干扰，需要新增算法）；实例分割（可给出逐对象掩码，但需另评估模型及部署，不作为本轮首选）。
- 比较结论：先选固定相对侧带。它能检验一致ROI规则的效果，但不保证每张都覆盖最易匹配的结构。
- 参数提案：侧带宽度 `roi.side_fraction=0.15`，浮点、占椅背宽度比例；上下裁去比例 `roi.vertical_trim=0.10`，浮点、各占高度比例。旧方案为逐图绝对坐标，无这两个参数。拟只运行上述一组值；0.10/0.20仅列为未来宽度候选，不在本轮自动试。带越宽点越多，也更易包含内部网纹；裁去越多可减少转角混入，但会损失有效部位。
- 评价：左右结果、候选数、窗口支持、对应点分布；不与原上端距离直接宣称严格同表面精度。
- 授权：待批准P1。

### R2：窗口是否完整位于指定目标范围内的掩码检查

- 所属环节：选点前的可用范围约束。
- 功能：发现中心在椅背上但9×9窗口明显跨入其他表面的情况。
- 输入：R1的区域掩码、匹配窗口尺寸。
- 输出：完整窗口支持掩码和跨边界点标记。
- 原理：对掩码侵蚀半个窗口的距离；只有窗口覆盖范围都在掩码内的中心点才具有完整支持。轮廓掩码不等于逐孔洞的实体像素标注，不能据此宣称网孔已分割。
- 待选方案：有。仅约束中心点（现有基线，点较多但窗口可跨界）；约束完整窗口（推荐诊断，归属清楚但窄框可能没有剩余位置）；按掩码加权匹配（能利用部分有效图块，但会改NCC度量，本轮不开发）。
- 参数提案：`support.require_full_window` 布尔值，比较false/true；`matching.patch_size=9`像素，半径4像素，保持原值。窗口5/7像素是后续候选，本轮不同时修改。
- 评价：分别显示只看中心与完整支持的结果；没有完整支持时明确记录该表面对当前窗口过窄，不通过降低门槛制造输出。
- 授权：待批准P1的掩码对照。

### R3：网格与Shi–Tomasi选点对照

- 所属环节：选点。
- 功能：在固定侧带内区分位置因素和选点方式因素。
- 输入：同一侧带及可用掩码。
- 输出：左图候选坐标。
- 原理：网格均匀覆盖位置；Shi–Tomasi优先选择两个方向灰度变化均明显的位置，并限制间距和聚集。
- 待选方案：有。网格（已有椅子候选，推荐为主对照）；Shi–Tomasi（现有v0.2方案，保留比较）；FAST/ORB（其他候选，先不新增，以免同时改变更多环节）。
- 参数提案：`grid_step=4`像素；Shi–Tomasi `quality_level=0.01`（相对角点响应阈值）、`min_distance=3`像素、`block_size=3`像素、`cells=3`（3×3分区）。全部保持基线值。主动点预算不超过网格数，另保留相同数量网格比较。降低质量阈值会增加弱候选，增加最小间距会减少聚集和总数；本轮不调。
- 评价：候选数、通过匹配数、分布、同数量对照，而非预设角点一定更好。
- 授权：待批准P1，复用现有实现。

### R4：局部NCC与上下窄带搜索

- 所属环节：左右对应。
- 功能：给定左点，寻找右图对应位置。
- 输入：左右校正灰度图与左候选坐标。
- 输出：左右完整坐标、最佳/次佳分数、拒绝原因。
- 原理：比较去均值并归一化后的局部明暗结构，选择外观相似且明显优于其他候选的位置。
- 待选方案：有。NCC（本轮固定，已有代码，便于只研究ROI）；Census＋汉明距离（按亮暗相对顺序比较，需新增实现）；ORB描述子匹配（另一套稀疏特征路线，改变选点和匹配两层）。后二者为P2候选，尚未证明优于NCC。
- 参数：窗口9×9像素、横向正视差1～127像素、纵向±8像素、图块灰度标准差≥5、NCC分数≥0.75、最佳与次佳差≥0.03，均使用现有值，本轮固定。窗口增大会混合更多表面；搜索变宽会增加候选与代价；放宽分数/差值门槛会增加点数与潜在错配。
- 评价：坐标对应的图示与逐点记录、拒绝原因；分数不作为准确率。
- 授权：P1只复用NCC，不开发替代匹配器。

### R5：三角化与中位数汇总

- 所属环节：几何计算及距离输出。
- 功能：对各侧带分别计算深度，不根据参考值选最好的区域。
- 输入：匹配坐标、现有P1/P2。
- 输出：矫正左坐标Z、重投影残差、各侧带中位数及正式输出状态。
- 原理：使用既有投影关系三角化，再汇总正且有限的深度。非零行差的残差单列，三角化不等于修复原模型。
- 待选方案：当前几何环节不列替换方案，因为本轮只控制ROI/选点；汇总可选整体中位数或分组后中位数，本轮固定前者。聚类或平面模型会引入新选择规则，另行批准。
- 参数：`min_points=30`有效点、`min_fraction=0.10`（分母是实际选点数），保持现有值；未达门槛的诊断中位数单列。放宽门槛可能恢复少点输出，但不是精度提升。相机基线5.85 cm及全部矩阵不改。
- 评价：输出率、共同样本误差、侧带间差异和残差。不自动融合左右侧带。
- 授权：P1只复用现有几何与汇总。

## 四、固定数据和执行顺序

1. 只用当前9对椅子图，不新增采集。冻结旧全部结果，旧7类ROI只作历史对照，不继续反复挑框。
2. 在不显示距离结果的情况下，标注每张可见椅背轮廓；公布轮廓、比例规则和生成侧带预览后再计算。
3. 计算两种窗口支持×两种选点的对照，同一NCC及相机关系；保存左右两带全部结果，不选取最贴近参考的候选充当成功。
4. 在少量匹配上提供可看清图案的左右放大图，记录明显属于椅背、背景或无法判断的位置，帮助区分有输出与对应正确。
5. 提交开发报告。边框与原上端参考部位不同，误差用作近似比较并分别报告，不宣称严格同表面验收。

本阶段不新增深度聚类、自动椅子检测或新匹配算法；书本和人物代码不修改。已有9对较少，用于本轮原因分析与算法比较，不宣称独立泛化测试。

## 五、反馈与结果判断

进度依次说明：ROI规则实现、掩码支持、选点对照、NCC执行、结果分析。每次给出完成的功能与已观察效果，尚无结果时写尚未评估。

报告包含每侧点数、通过率、正式输出/诊断值、重投影残差、可视对应与耗时；分别比较共同可输出样本及输出率。同步保留失败图，不仅展示最好的6张。

如果固定区域及完整窗口支持能恢复更多正确对应，优先完善ROI规则；如果区域归属清楚但仍大量错配，下一步转P2匹配算法对照；如果可靠点存在却不足30个，另提稀疏输出规则方案，不把它与匹配故障混为一谈。
