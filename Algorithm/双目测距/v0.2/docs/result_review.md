# v0.2方案A开发反馈

2026-11-21。方案A已实现并完成43对评估；只新增主动选点，ROI、NCC、深度方向、相机参数和中位数统计保持固定。v0.1未修改。

## 1. 新增算法完成了什么

流程为：校正图 → 原人工ROI → Shi–Tomasi角点 → 3×3分区与数量限制 → 原NCC窄带匹配 → 原P1/P2三角化 → 深度中位数。

Shi–Tomasi寻找两个方向均有明暗变化的位置，适合文字拐角或图案交点。它负责选择更容易定位的点，不负责识别物体或辨别背景。实现使用OpenCV的 `goodFeaturesToTrack`，无需训练。[算法说明](https://docs.opencv.org/4.x/d4/d8c/tutorial_py_shi_tomasi.html)

新增 `selection.py` 有中文注释。NCC及几何模块从v0.1独立复制，数值代码未改；没有引入反查。

## 2. 怎样比较

- **原网格**：保持v0.1的4像素间隔网格及NCC。
- **同数量网格**：按主动角点实际数量，从原网格中均匀抽取相同数量的点。
- **主动角点**：Shi–Tomasi选点后送入同一NCC。

三种方法都使用30个有效点、10%通过比例门槛。参考距离为原采集近似记录，只在计算结束后报告误差。空间覆盖以3×3格数描述，不把它写成物体像素覆盖率。

## 4. 输出缺失与仍未解决的问题

书本的 `PartB/0020` 仅27个有效点；`0021～0025` 是全部3米图，主动候选总数仅21～26个，有效点16～22个，因30点门槛未正式输出。它们的诊断中位数仍约2.60～2.69 m，不能把不输出理解为误差消失。

人物 `PartC/0003` 上一轮原网格通过比例8.45%，未输出；本轮主动选点保留56/465点，比例约12.0%，恢复输出，测得0.815 m（参考0.98 m）。这主要是选点效率改善。

人物 `PartC/0015` 仍测得约2.041 m（参考2.98 m），此前观察到的拍摄期间人物变化仍需单独理解。

椅子可以选出27～61个角点，但NCC最终仅保留0～3个。说明“左图像角点”还不足以保证右图存在可区分对应；窄上沿、弱纹理/重复纹理及当前几何残差问题仍在。0010的3个点诊断中位数约1.94 m，接近参考不代表已经能可靠代表椅背。

## 5. 点数与计算代价

书本平均待匹配点从474降至138，人物从528降至231。书本NCC匹配本机平均约26.1→9.9 ms/对，人物约28.0→14.3 ms/对；主动选点自身全体平均约5.6 ms/对。计时为ROI稀疏匹配，未含完整读图、校正、三角化和写盘，也未做树莓派测速。

角点名额和空间限制减少了无效搜索，但也使远处小目标不足30点。这是稀疏测距输出规则需要单独审议的地方。本轮没有调整门槛恢复输出。

## 6. 下一步方案，待批准

建议优先研究**目标表面候选区**，而不是立即更换Census、放宽NCC或保留反查。

预选方案：继续使用 **Shi–Tomasi＋NCC**，人工指定更完整的目标表面范围，拆成若干实体子区，观察哪些子区有可靠对应。人物仍测躯干，椅子仍对应原椅背参考部位。先看外观决定候选区，不根据测得距离挑区域；不跨到坐面后继续沿用椅背参考值。

这一轮可以回答“目前椅子的失败，是否主要被窄上沿ROI限制”。使用现有图像，不新增采集，不接YOLO。深度分组、背景辅助及稀疏点输出门槛的调整再单独说明并取得授权。

本次完成的是v0.2方案A的主动选点开发与比较，不代表整套实时目标测距已经完成。后续方案尚未执行。
