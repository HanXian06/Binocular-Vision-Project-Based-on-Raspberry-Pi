# YOLO检测→自动选区→v0.1稠密测距：开发前审阅方案

2026-11-23。状态：待用户选择并批准实施；本次完成ROI协议和两版最终评估，不实施YOLO融合及新上下搜索。

## 一、仓库核对

仓库main提交 `7ee347e136078f3784885fd0ae3ee77dc016c870`：`Algorithm/Dual-Camera-YOLO/`中为YOLOX-Nano，模型 `yolox_nano.onnx`（3,659,407字节）。代码只读核对，未改仓库。

- `detect.py`：两路常开后依次 `capture_array/read`，分别推理；相机配置640×480、15fps是采集配置，不是已测双目测距帧率。
- `yolox_backend.py`：OpenCV DNN，416输入，等比例缩放后放在左上，右/下补114。`objectness×class_probability`，按类NMS。默认置信度0.35、NMS IoU 0.45，类别含person/chair/book。
- `Detector.annotate(frame)`仅返回绘制图和类别名；内部已经算出box/prob/class，但没有结构化返回，不能靠读取画框图片做测距。
- 保留原BGR、blob预处理与输出解码方式，先复用已有权重，不换成其他YOLO系列或分割模型。源码只读快照在本目录 `github_detect.txt`、`github_yolox_backend.txt`、`github_README.md`。

源码链接：[检测入口](https://github.com/HanXian06/Binocular-Vision-Project-Based-on-Raspberry-Pi/blob/7ee347e136078f3784885fd0ae3ee77dc016c870/Algorithm/Dual-Camera-YOLO/detect.py)、[后端](https://github.com/HanXian06/Binocular-Vision-Project-Based-on-Raspberry-Pi/blob/7ee347e136078f3784885fd0ae3ee77dc016c870/Algorithm/Dual-Camera-YOLO/yolox_backend.py)。

## 二、目标与流程

目标是自动目标距离，不再反复手工局部框选。算法主线以v0.1稠密视差为基础，保留远处无角点时计算深度的能力，不引入Shi–Tomasi作为必需入口。

原左右帧与时间记录 → 相机校正 → 校正左图YOLOX检测 → 结构化检测结果 → 类别表面适配器 → 固定多区域协议 → 稠密匹配及深度 → 每个检测目标的距离、状态和区域依据 → 最后绘制。

初期只需左图检测来关联左视差；右图提供对应信息。右图检测可留作显示或后续验证，不作为首版必需的双框配对步骤。绘制图不进入匹配。保留逐次采集时间，软件配对不当作同时曝光。

## 三、算法卡与待选比较

### D1：现有YOLOX-Nano＋按类NMS

环节/作用：检测。输入校正左图BGR，输出 `detection_id,class_id,class_name,score,xyxy`。原理为神经网络预测物体框，置信度筛选后NMS合并重复框。新增 `infer()`结构化接口，`annotate()`复用结果，避免重复推理。

备选：现有YOLOX（推荐，已部署且可复用）；换检测模型（需重做部署比较）；实例分割（能给像素归属，但不能修正双目对应，当前不首选）。本阶段不训练。

参数：输入416保持模型要求；置信度0.35、NMS IoU 0.45均沿用。提高置信度减少低分框也会漏检；提高IoU保留更多重叠框。本阶段不扫描阈值。

评价：检测是否命中目标、漏检/多目标、框坐标还原、推理耗时。检测分数不当作深度准确率。授权：待批准。

### D2：类别表面适配＋固定多区域协议

输入为每个检测框及类别，输出校正左图表面框与13候选。先用相对比例从整物体框获得预期表面，再调用已经冻结的ROI协议。独立输出每个目标，不因存在多把椅子而只挑最靠近参考的框。

备选：整框中位数（最简单但背景多）；类别相对表面＋多区域（推荐首版，固定且可解释）；实例掩码（后续候选，额外模型/推理代价）。

拟用比例：book内缩5%；person取框内x20%～80%、y15%～65%的躯干；chair取框内x5%～95%、y5%～55%的上部椅背候选。它们是待批准的首版几何先验，实际姿态下需评估；不能把它们称为椅背精确分割。表面内完整区/中心/左右带/九宫格使用冻结协议参数，不在每次失败后换比例。

框恢复：当前后端左上补边，坐标除缩放比恢复，不套用中心补边公式。若输入是校正图，输出也应回到同一640×480校正图；不混用原图框与校正图深度。边界取整/截断规则固定，并记录变换。

评价：实际YOLO输出驱动的全部候选和最终结果；检测缺失单列，不能偷偷用人工框补齐再报告自动成绩。授权：待批准。

### M1：先接通原v0.1 SGBM作为集成基线

输入校正左右灰度图，输出全图稠密视差、有效掩码；ROI只影响读取和统计，不先删掉远处弱角点区域。原理是局部代价＋多方向聚合与视差连续性惩罚。

现有参数：min_disparity=0、num_disparities=128、block_size=5、P1=200、P2=800、uniqueness_ratio=10、speckle_window_size=100、speckle_range=2、disp12_max_diff=1。复用现有Q及米单位，独立右匹配反查不默认加入。

范围宽度控制可搜索深度，窗口扩大易混合表面；P1/P2控制视差跳变惩罚，唯一性与散斑会改变有效点数量。首阶段固定这些参数。

备选：原SGBM（推荐集成基线）；下面M2真正的纵向搜索稠密方案；v0.2稀疏主动点（保留实验，不进入主线）。授权：先请求批准自动检测到原SGBM的闭环；不能把该阶段写成已实现上下搜索。

### M2：上下搜索的稠密方案——需要用户选型

现有OpenCV StereoSGBM没有“上下搜索半径”参数，增加纵向候选不是改一个配置值。推荐候选A保持稠密视差路线；不把v0.2的Shi–Tomasi/NCC替换过程包装成v0.1升级。

**候选A：纵向最小匹配代价＋SGM聚合（推荐符合需求的方向）。** 对每个像素与横向视差，比较右图上下候选行的Birchfield–Tomasi局部代价，保留最佳行偏移，再用SGM多方向聚合选视差。保存dx、dy和代价，而不只输出dx。优点是让纵向候选直接进入稠密匹配；不足是需要自定义代价体和聚合实现，OpenCV现有Python接口不能直接塞入自定义代价体，实现及计算代价明显高于选区适配。

**候选B：先二维配准，再原SGBM。** 用图案对应估计图像间的纵向补偿后匹配，较容易复用原程序；但已有行差随距离/位置变化，一个全局上移量不能覆盖全部，且变换后的投影关系要维护。它是输入对齐，不是逐像素上下探索。

**候选C：SGBM初值＋局部二维修正。** 保留原稠密初值，在检测区域内围绕初始位置比较附近二维候选；能控制计算量，但初值严重错误时小范围无法纠正，新增局部度量也要选型，不默认采用NCC。

A的参数提案：纵向半径0/2/4/8像素（0为消融基线）；横向宽128，块边长5；BT预滤波和截断需明确与原实现的对应；SGM初始P1=200/P2=800仅在代价尺度一致时沿用，尺度不同时先提交新的数值理由。聚合方向数、分块内存预算、亚像素拟合与筛选规则均在实现前固定。扩大半径增加内存/计算和歧义；不依据参考距离选纵向行。

评价：同一自动检测和ROI规则下，比较δy=0与允许纵向候选的对应、共同样本误差、输出率、远书本与椅子表现、内存/延迟。自定义SGM不能宣称与原OpenCV逐位一致，需用0纵向搜索基线核对行为再比较。

授权：M2当前仅方案，建议用户先选A/B/C并批准具体实现范围。

### G1：几何计算与目标距离汇总

M1使用原Q；M2保留完整左右坐标并核对投影关系和重投影残差。原相机参数和5.85cm基线不重标定。主输出明确是矫正左坐标Z，其他轴向距离另列，不用改距离定义制造精度提升。

采用冻结协议的候选位置并集去重后中位数，min_count=30、min_fraction=0.1保持不动。备选为深度聚类后选目标组，但这是新的归属/统计算法，当前不自动加入。输出含类别、框、深度、状态、有效数量与比例，而不只绘制一个距离。

当前表面近似仍会混入网孔背景；若自动框已稳定而多簇问题突出，再单独提交聚类或实例分割算法比较。授权：待批准集成，不等于批准后续聚类。
