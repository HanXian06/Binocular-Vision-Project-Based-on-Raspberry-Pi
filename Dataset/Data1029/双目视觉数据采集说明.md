# 双目数据采集操作指南

目前两只摄像头已经横向并排安装。本指南按“先检查、再标定、再测距”的顺序操作，不用一次拍完所有数据。

## 一、开始前记下这些信息

在纸上或文本里记录：

- 两只镜头中心之间的距离：____ 毫米（用尺量近似值即可）。
- 哪只是左相机、哪只是右相机：L 对应 camera __，R 对应 camera __。
- 摄像头型号：____；本次每路拍摄尺寸统一为 **640×480**。
- 棋盘格：横向 __、纵向 __ 个内角点；实际每格边长 __ 毫米。
- 拍摄日期、地点、负责人；拍一张能看见两只相机的安装照片。

拍完标定图以后，不要再挪动两只相机的相对位置或调整镜头。如果改了，需要重新拍标定图。

## 二、用哪个程序拍？

原来的 `dualcam.py` **只能取图和显示，不能保存照片**。它显示的画面还把每路缩小了。

已另存新程序 **`capture_pairs.py`**，原程序没有修改。新程序沿用原来的轮流拍摄方式，每按一次 **S**，保存左、右各一张 640×480 PNG，再显示拼接预览。

**这是静态拍摄程序，两张不是同时拍的。按 S 后保持棋盘格或物体不动，直到终端提示“已保存”，通常需要约 4 秒或更久。** 当前不要用它采集行走的人或移动物体。

### 1. 把新程序传到树莓派

1. 用 WinSCP 连接树莓派。
2. 将本电脑 `csicam-python` 文件夹里的 `capture_pairs.py` 上传到树莓派的 `/home/pi/csicam-python/`。若你们实际文件夹不同，后面的命令相应修改。
3. 用 VNC 打开树莓派桌面，关闭正在运行的其他相机程序，避免相机被占用。
4. 在树莓派桌面打开终端，执行：

```bash
source /home/pi/csicam/bin/activate
cd /home/pi/csicam-python
python capture_pairs.py --out /home/pi/stereo_data/check_01
```

以上虚拟环境路径来自现有 `csicam/pyvenv.cfg`；如果树莓派上的路径已经改变，使用实际路径。不要在 Windows 上运行这个脚本。

### 2. 拍第一对并核对左右

1. 程序会打开黑色图像窗口。**先点击图像窗口，再按 S，不用按回车。**
2. 保持场景不动，直到终端显示“已保存 pair_0001”。
3. 窗口左半是程序认定的 L，右半是 R。默认 camera 0 为 L、camera 1 为 R。
4. 核对方法：只遮住物理左相机的镜头拍一对，检查是否仅左半变暗。左右对应反了，就退出并按下面的交换命令重开。这对遮挡照片只作检查。
5. 移开遮挡，再拍几对普通场景，检查清晰度、亮度和目标是否两边都看得见。
6. 按 Q 退出。按键都需要让图像窗口处于选中状态。

如果左右反了，运行：

```bash
python capture_pairs.py --out /home/pi/stereo_data/check_02 --left-camera 1 --right-camera 0
```

以后每次都带上同样的左右编号选项。

**窗口显示的是上一对照片，不是实时画面。** 移动棋盘格后，按 S 才会更新。先拍、看结果、再调整即可。若需要提前实时取景，可先用原来的 `dualcam.py` 看好构图，再退出原程序、启动采集程序，不能同时运行两者。

每次 `--out` 都要指定一个**尚不存在的新文件夹**。已有目录会报错退出，这是为了防止覆盖旧照片；第二次采集可改为 `calib_02` 等名字。

## 三、第一批：检查图，约 5 对

用上面的 `check_01` 目录拍摄。放一本书或有图案的盒子，确认：

- 左右对应正确，两个画面都清楚，物体没有被切掉。
- 左右颜色和亮度没有明显异常。
- WinSCP 能找到左右图片，传到电脑后能打开。

若启动后拍到的图明显忽明忽暗，可试着在新目录增加等待时间：

```bash
python capture_pairs.py --out /home/pi/stereo_data/check_03 --warmup 3
```

这只增加每路启动后的等待时间，不能让左右同步。亮度仍不稳定时先排查，不急着批量拍。

## 四、第二批：棋盘格标定图，先拍 20 对

### 准备棋盘格

- 推荐准备 **10×7 个黑白方格**，对应 **9×6 个内角点**。内角点是内部黑白格交界的点，不是方格个数。
- 每格可先按约 25 毫米准备。打印后用尺量实际格长，横竖都检查，记录实际值。
- 平整贴在硬板上，不要拿一张会弯的纸直接拍。
- 每张都要让左右相机看见**完整棋盘格及一点周围空白**；避免反光、模糊和格子太小。

启动新的采集目录：

```bash
python capture_pairs.py --out /home/pi/stereo_data/calib_01
```

如果左右编号交换过，记得加 `--left-camera 1 --right-camera 0`。

### 20 对具体怎么拍

相机始终不动，只移动棋盘格。每个位置拍 **1 对**，也就是按一次 S。摆好、放稳，再按 S；两张都保存成功后才换位置。

下面的“左、右、上、下”都以拍出的画面为准。靠边时不能把棋盘格移出任何一路画面。

| 配对编号 | 棋盘格怎么摆 |
| --- | --- |
| 0001 | 中间，正对相机，大小约占画面宽度一半 |
| 0002 | 比上一张靠近一些，正对相机，约占画面宽度三分之二 |
| 0003 | 比第一张远一些，正对相机，约占画面宽度三分之一，格子仍要清楚 |
| 0004 | 回到中等距离，正对相机，稍微顺时针转一点，像把照片转斜约 15° |
| 0005 | 同样在中间，改成逆时针转约 15° |
| 0006 | 中等距离，平移到画面偏左，仍保持完整可见 |
| 0007 | 平移到画面偏右 |
| 0008 | 平移到画面偏上 |
| 0009 | 平移到画面偏下 |
| 0010 | 平移到画面左上区域 |
| 0011 | 平移到画面右上区域 |
| 0012 | 平移到画面左下区域 |
| 0013 | 平移到画面右下区域 |
| 0014 | 回到中间，棋盘格左边靠近相机、右边远离，约倾斜 20°～30° |
| 0015 | 反过来：右边靠近、左边远离 |
| 0016 | 上边靠近、下边远离，约倾斜 20°～30° |
| 0017 | 下边靠近、上边远离 |
| 0018 | 稍近一些、位置偏左，轻微倾斜，换一种前面没有的姿态 |
| 0019 | 稍远一些、位置偏右，轻微倾斜，保证格子清楚 |
| 0020 | 查看前面照片，补一个覆盖不足的位置，例如靠上但略倾斜 |

这些角度不需要用量角器精确测量。**“稍近、稍远”不用量米数，以画面中的大小为准。** 拍摄时可借桌面或支撑固定棋盘格，避免轮流拍两张期间手抖。

每拍一对就看拼接预览：两边都完整、清楚才继续。拍坏了不用删，记下编号，补拍一对并注明替代关系。算法同学检查两路角点和校正效果后，若不够合格，再补到约 30 对。

**这一批不用测棋盘格到相机的距离。** 需要交付的是图片、实际格长、内角点数。相机焦距、畸变等参数由后续程序算出，不需要现场手算。

## 五、第三批：已知距离测距图，5 个距离各 5 对

标定图可用后再拍这一批；首次时间不足可以下次做。

### 目标与距离怎么量

1. 用一块平整、有文字或图案的纸板作目标，尽量正对相机。先不选白墙、玻璃和反光物体。
2. 相机尽量水平，将纸板放在左相机前方，两路都能看到，距离测量方向也沿相机前方。
3. 在左镜头旁的支架上标一个固定测量起点，尽量与左镜头中心处于同一前后位置，拍照记下。从这里沿前方量到纸板**朝向相机的表面**，不要量到纸板后面的墙，也不要量到树莓派外壳。
4. 可以把相机参考位置和纸板表面投到地面，再在地面量前后间距。记录起点位置及尺子的读数精度；这个起点只是近似参考，算法同学比较精度时需要考虑它与相机光心的偏移。
5. 纸板可以贴一个小标记，说明后续取哪块区域测距；不要在原图上直接画框。

启动：

```bash
python capture_pairs.py --out /home/pi/stereo_data/range_01
```

| 大约距离 | 拍多少 | 拍法 |
| --- | --- | --- |
| 0.5 米 | 5 对 | 每次重新摆放、量距离、放稳，再按 S |
| 1.0 米 | 5 对 | 同上 |
| 1.5 米 | 5 对 | 同上 |
| 2.0 米 | 5 对 | 同上 |
| 3.0 米 | 5 对 | 同上；拍不清或测不出，也记下情况 |

不要求恰好摆在整数距离。计划 1 米，尺子量到 1.02 米，就写 **1.02 米**。不要不动目标连拍 5 次，代替 5 次重新摆放。

### 每拍一对要记什么

程序会在该目录生成 `measurements.csv`，每保存一对自动新增对应编号的空白行。**距离需要人工填写，程序不会自动知道。** 可以现场先写在纸上，退出程序后再填写表格，不要在程序运行时同时编辑它。

| 编号 | 目标 | 实际距离（米） | 量到哪个面 | 备注 |
| --- | --- | --- | --- | --- |
| pair_0001 | 图案纸板 | 填实际读数 | 纸板正面 | 正常／模糊／其他 |

CSV 中 `target` 填目标，`actual_depth_m` 填实际距离，`reference_surface` 填参考表面，`pose_or_position` 可填位置或姿态，`notes` 填其他说明。标定图只需记录姿态，不用填实际距离。

## 六、图片保存在哪里？需不需要拼一起？

**保存两张独立原图；拼接图只用于检查，不作为主要交付。** 程序保存的 PNG 没有缩小、画框或校正。“原图”在这里指未经这些处理的相机输出，不需要另外拍 RAW。

例如：

```text
calib_01/
  left/
    pair_0001_L.png
    pair_0002_L.png
  right/
    pair_0001_R.png
    pair_0002_R.png
  metadata/
    pair_0001.json
    pair_0002.json
  capture_setup.json
  measurements.csv
```

- 左右文件的编号相同，就是一对。`calib_01 + pair_0001` 一起确定这次采集的某一对，跨文件夹编号重复没有问题。
- `metadata` 保存程序取得的时间和相机信息，用于排查；它不表示左右已经同步。
- 安装信息、棋盘格格长和测量起点说明，可另写 `notes.txt` 放进同一个目录。
- 通过 WinSCP 把整个 `calib_01` 或 `range_01` 文件夹传回电脑，不只传 `left`。
- 检查左右图片数量一致、同编号都齐全，随机打开几对确认尺寸和清晰度。VNC 截图不能代替这些图片。
- 拍坏的编号在记录中标“无效”。左右不要单独重新编号，也不要将不同编号凑成一对。

## 七、后面再补什么数据？

| 批次 | 什么时候拍 | 起步工作量 |
| --- | --- | --- |
| 检查图 | 现在 | 约 5 对 |
| 棋盘格标定图 | 检查通过后 | 约 20 对，不够再补 |
| 已知距离测距图 | 标定可用后 | 5 个距离×5 对，共 25 对 |
| 真实场景图 | 基础测距跑通后 | 人、椅子各在约 1、2、3 米拍 3 对，共 18 对；人先站稳 |
| 独立测试图 | 算法参数固定后 | 另一次重新拍 5 个距离×5 对；不要用调参时的旧照片代替 |

真实场景也要记实际距离和量到的表面，例如人的胸前、椅子靠背；程序需要比较同一块表面。之后再按需要加暗光、遮挡、反光等场景，每种先拍 5 对。现在不用大量拍视频，也不用先做大规模训练集。

## 八、以后调整双目位置，怎么补拍？

第一版先不改安装。跑通后可优先尝试“间距稍大或稍小”，每次只改一项。

- 新方案另起名字，如 `rig02`，记录新间距和安装照片，图片另存。
- 先拍 5 对检查图，再重新拍约 20 对棋盘格，重新标定。
- 先在 0.5、1.5、3 米各拍 3 对，比较是否更好；有改善再补完整测距集。
- 旧数据和旧参数都保留，新安装不要直接用旧的双目标定参数。

**“一前一后”不作为优先改法。** 两只都朝前且几乎前后重合时，正前方目标反而难测，前面的相机还可能挡住后面的；若分别朝前、朝后，看不到共同目标，则不能按现在的方法做双目测距。上下放置、明显向内转等方案还需要调整算法，不能只换位置就继续用原来的参数。

## 九、遇到问题先看这里

- **没有图片窗口或 `imshow` 报错**：在 VNC 的树莓派桌面终端运行；不要从没有图形桌面的会话启动。
- **相机打不开**：关闭原预览程序，确认两路原程序都能取图，再重试。
- **目录已存在**：换一个新目录名，不需要删除已有照片。
- **提示找不到 Picamera2 / cv2**：确认已经进入原来能运行 `dualcam.py` 的 Python 环境，不要先重装系统或驱动。
- **按键没反应**：先点击图像窗口；拍摄过程中等待“已保存”，不要连续按 S。
- **中途报错**：先保留终端报错和已经保存的目录，检查最后一对是否齐全；下次换新目录继续。

新脚本在电脑端只做语法及模拟流程检查，尚未在你们的树莓派上实拍验证。先拍检查图，确认无误后再拍正式数据。
